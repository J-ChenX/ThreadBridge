# 多机接入与统一启停

## 配置与职责

当前实现支持一个 Hub 电脑和最多三个远端，合计四个 host。每台具有独立身份、捕获库、版本配置与队列账本。远端固定 Python RPC 通过已信任 SSH/Tailscale 传输，操作白名单、响应大小和时间有界；不提供任意 shell 业务接口。Linux 和 Windows 使用各自命令格式。

私有清单位于 `local/fleet/fleet.json`，模板为 `deploy/fleet.example.json`。填写 binary、hub_db、主机 ID、SSH、Python、helper、Codex 路径和 CODEX_HOME。`verified_version` 默认 null，即只读；必须验证该主机原 ID 与上下文后再填精确版本。SSH 使用 BatchMode、StrictHostKeyChecking 和超时，先配置密钥与 known_hosts，不在运行时绕过主机指纹。

```sh
mkdir -p local/fleet
cp deploy/fleet.example.json local/fleet/fleet.json
# 编辑为自己的已有主机和受保护路径
python3 scripts/fleet.py --config local/fleet/fleet.json probe
```

`deploy` 安装远端 helper 与依赖，`install` 修改本机用户服务定义；这些是部署操作，应先检查私有配置和既有服务。在已配置环境使用：

```sh
python3 scripts/fleet.py deploy
python3 scripts/fleet.py install
python3 scripts/fleet.py start
python3 scripts/fleet.py status
```

## 生命周期与运行边界

`start|stop|restart` 统一控制 `threadbridge.target`，无需分别登录各电脑。target 包含既有 `threadbridge-phone-hub`、`threadbridge-phone-inbox`、`threadbridge-phone-capture`，以及安装时生成的 remote 实例。`install` 不替用户创建这三个本机基础服务，需先按 [运行与安装](运行与安装.md)建立 Hub/queue/capture。

远端 `run` 持续读取完成轮次，将独立捕获库同步到本机受保护目录并幂等导入 Hub。目标身份始终由主机 ID 和原生 thread ID 决定，不按标题路由。发送代理只调用已验证版本 queue。网络失联停止刷新发送就绪状态，已保存历史仍可阅读；重新连接只核对原请求，不重放 unknown。

采集使用 `.collection.json` 的 cutoff、完整旧 ID 排除集和 generation。清理前的目标不能因继续聊天重新进入。删除只清理 ThreadBridge 副本；原 Codex 对话和配对保留。策略、墓碑与必要去重回执不因正文删除而丢弃。清理操作由 `scripts/reset_collection.py` 提供，它会影响共享副本与手机缓存，不能当作普通状态检查运行。

`capture_health.py` 提供持久失败状态；`recover_capture_health.py` 可检查源/索引、孤立部分 turn、缺失输入和容量边界。异常恢复不发送消息，不把时间邻近当作旧未知请求已经成功的证据。持久记录格式和采集来源依赖实际安装版 Codex。

## 备份、回退与验收

`fleet.py install` 在 `local/backups/fleet-*` 保存原服务定义，创建 target、remote 模板和本机 `80-fleet.conf` drop-in。回退时先停止 target，按该备份恢复具体服务片段，保留其他 drop-in，执行 `systemctl --user daemon-reload` 后启动所需服务。不要用旧正文数据库覆盖当前 collection 状态。

开机启动需结合用户服务 enable 和用户登录/linger 状态设置，并单独进行整机重启验收。已有四机指定对话测试不等于全部日常验收完成。

`tests/python/test_fleet.py` 覆盖固定 RPC、快照、健康、传输与故障边界；`tests/run.py` 覆盖回环收发和重启。不在这些隔离测试中登录真实电脑。实机验收包含各系统版本、原 ID/上下文、停止后就绪撤销、重连、未知请求保持和长时间资源测量。
