# 运行与安装

## 构建与安装

工具版本及完整检查见 [开发与发布](开发与发布.md)。`scripts/build-apk.sh` 输出 `artifacts/ThreadBridge-0.1.14.apk` 和 SHA-256；安装包不放入源码仓库。传到手机后允许该来源安装，已有版本直接覆盖。升级必须沿用原签名，不通过卸载绕过数据库兼容问题。

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
export THREADBRIDGE_KEYSTORE=/protected/path/threadbridge.jks
# THREADBRIDGE_KEY_PASSWORD 从本机秘密存储加载
scripts/build-apk.sh
```

包名 `dev.threadbridge`，当前 versionName `0.1.14-test`、versionCode 15、Room 3。Keystore 和密码属于部署者，不提交仓库。未设置公共测试地址时，应用不预置实际服务器；`THREADBRIDGE_PUBLIC_TEST_SERVER` 等构建变量仅用于自己的已验证 HTTPS 入口。

构建脚本串行执行 JVM、release 和 Lint，验证签名和 16 KiB 对齐，按 APK 元数据命名输出。用 `python3 scripts/verify-release.py NEW.apk --previous OLD.apk` 核验包名、版本递增和同签名。

## 隔离单机演示

```sh
cargo build --release --locked
mkdir -p local/demo
target/release/threadbridge register-agent --db local/demo/hub.sqlite --name '本机演示' --output local/demo/agent.json
target/release/threadbridge combined --db local/demo/hub.sqlite --config local/demo/agent.json --listen 0.0.0.0:8787 --demo
```

`--demo` 不读取或运行真实 Codex。仅在受信任局域网使用，手机输入 `http://电脑局域网IP:8787` 并启用局域网测试。公网需要正确的 HTTPS 入口。

另开终端生成 5 分钟单次配对码：

```sh
target/release/threadbridge pair --db local/demo/hub.sqlite --url http://电脑局域网IP:8787
```

输入 code 或将完整配对 JSON 生成为二维码。长期凭证不进入 URL。首次配对可验证演示收发、草稿、进程重开、离线阅读和重连。关停用 Ctrl-C；凭证可用 `revoke` 撤销。一次性码和生成的 agent.json 不上传。

## 真实完成捕获与续聊

通知转发配置直接调用二进制的 `capture` 子命令，例如 `notify = ["/absolute/path/threadbridge", "capture", "--database", "/protected/path/replies.sqlite", "--all-tasks"]`；事件 JSON 由上游作为最后一个参数追加。旧 `scripts/capture_catalog.py` 仅转交同一 Rust CLI，构建二进制后可暂时保留原 notify 配置；`THREADBRIDGE_BINARY` 可指定安装位置。按需要选择 `--catalog` 白名单或 `--all-tasks`，并指定独立 capture 数据库。示例清单为 `deploy/capture-catalog.example.json`，须替换为自己的原生 thread ID。`--title-index` 只读取标题元数据；`--user-turn-index` 显式启用当前完成轮次用户消息读取。

collection 策略保护是所有当前采集路径的前提；策略无法核对时停止，不为恢复内容而删除策略文件。部署过程先保存配置和数据库快照，再设置授权范围和新对话 baseline。[多机接入](多机接入.md)说明 remote 采集及统一服务管理；[Codex 接入](modules/Codex接入.md)说明持久格式依赖和缺失通知边界。

```sh
target/release/threadbridge capture-sync --db /path/to/hub.sqlite --capture-db /path/to/replies.sqlite --host HOST_ID --all-captured --native-index /path/to/.codex/state_5.sqlite
```

默认队列续聊使用以下入口。`VERIFIED_VERSION` 必须是该主机已通过原 ID/上下文验收的精确 `codex --version` 字符串，不能直接照抄其他主机的值：

```sh
target/release/threadbridge capture-bridge --db /path/to/hub.sqlite --capture-db /path/to/replies.sqlite --host HOST_ID --codex /path/to/codex --allow-queue --verified-version "$VERIFIED_VERSION"
```

不传 `--thread` 时发现全部已捕获对话，传入 UUID 可限制范围。仅手机主动提交的消息进入原任务 queue；upstream_queued 不等于开始执行，可能等待桌面激活。unknown 不重发。

## Rust Hub / Agent 与 TLS

`hub --db PATH --listen 127.0.0.1:8787` 启动 Hub。`register-agent` 为每台执行电脑建立独立配置；凭证文件 0600，Hub 只保存摘要。远端连接改为验证过证书的 HTTPS 地址。

```sh
target/release/threadbridge agent --config /protected/path/agent.json --db /protected/path/agent.sqlite --socket /path/to/existing-app-server.sock
```

此路线只附着已有 App Server。核验端点归属、原 ID、重启和并发后才设置 `--verified-version`，不存在端点时不能把桌面私有工具管道作为替代。`combined` 共享运行时和数据库；独立 Agent 主动 WSS。电脑间 Tailscale 传输仍需要应用鉴权。

`deploy/threadbridge.service`、`threadbridge-agent.service` 是独立模式模板，路径需要适配；`deploy/threadbridge.target` 是现有 capture/queue 三服务分组模板，不可把二者当成完整的一键部署。真实多机安装由 `threadbridge fleet install` 为既有本机服务创建 drop-in 和 remote 单元。

`deploy/Caddyfile.example` 展示本机 TLS 反代。使用 cpolar 时核验 TLS 透传/终止位置、证书和 WebSocket；HTTPS 域名本身不证明外部中继看不到正文。

## 通知

Hub/combined 可设置 `THREADBRIDGE_NTFY_URL=https://你的ntfy服务/受保护主题` 及 `THREADBRIDGE_NTFY_TOKEN`。通知仅通用更新提示与深链接，正文和授权令牌不进入推送。首次导入历史不通知，outbox 24 小时有效、最多重试 5 次。服务商接收不代表手机已显示。

环境文件可放 `~/.config/threadbridge/notification.env`，权限 0600。接入已有 notify 钩子时保留它的原配置，避免重复推送。APK 当前不直接注册 UnifiedPush/FCM。

## 备份与恢复

```sh
target/release/threadbridge backup-bundle --hub-db local/hub.sqlite --agent-db local/agent.sqlite --credential-file local/agent.json --signing-dir local/signing --destination local/backups/manual-01
```

SQLite 使用一致性备份，包含 WAL 提交数据；combined 的 Agent 账本已在 Hub 中，不重复传 agent-db。备份不创建定时任务，不覆盖旧目的地；含凭证与签名时放受保护或加密本地存储。原 Codex 工作目录独立备份。

先停服务，再恢复到新路径：

```sh
target/release/threadbridge restore --backup local/backups/manual-01/hub.sqlite --destination local/restored-hub.sqlite
```

恢复默认关闭写入、撤销旧设备并停止旧通知重放；先核对 Agent 账本和原 Codex 状态，再配对并执行 `enable-writes --reconciled`。不能删除未知命令来解除 unknown。

collection 重置或删除后，不恢复旧的含正文副本来绕过当前策略。签名密钥、身份与必要去重账本和正文副本有不同保留规则。完整实机、锁屏、资源和持续运行验收仍见 [架构入口](ARCHITECTURE.md)。
