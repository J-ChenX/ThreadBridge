# 通信与存储

## 协议与鉴权

协议版本 1；模型见 `crates/threadbridge/src/model.rs`。手机和 Agent 使用不同角色的 256 位随机 bearer 凭证；Hub 只保存 SHA-256 摘要。单用户手机访问已注册的全部主机；每个 Agent 只能更新由其主机身份派生的任务与回执。配对码有效 5 分钟、单次使用；设备凭证有效 90 天，可独立撤销，过期重新配对。任务键为主机、default 配置实例、原生任务 ID 的哈希。

| 接口 | 合同 |
|---|---|
| `GET /health` | 不含敏感信息的协议健康状态 |
| `POST /v1/pair` | `{code,name}` 换取设备凭证；唯一公开写入口，20 次/分钟全局限流 |
| `GET /v1/hosts` | 已注册主机与最后在线时间 |
| `GET /v1/threads?offset=0` | 每页 50 个任务，返回事件基准游标、可选消息变化标记与毫秒级活动时间 |
| `GET /v1/threads/{id}/messages?before=...&before_id=...` | 最多 30 条，正文首段合计约 256 KiB；用 next_before / next_before_id 复合游标续页 |
| `GET /v1/threads/{id}/messages/{message}/body?version=...&offset=...` | 同版本正文分段；版本不一致返回冲突 |
| `POST /v1/commands` | 不可变 request_id、thread_id、text、expected_revision、created_at、kind、cursor |
| `GET /v1/commands/{id-or-request-id}` | 仅原提交设备可查询 |
| `POST /v1/commands/{id}/cancel` | 仅在 accepted、尚未分发时取消 |
| `GET /v1/events?after=...` / `/v1/events/ws` | 持久游标、每批 100 事件，过期要求刷新投影 |
| `/v1/agent/ws` | hello、snapshot、receipt、heartbeat、明确删除事件；凭证绑定主机 |

错误包括 unauthorized、idempotency_conflict、revision_conflict、not_ready、host_offline、queue_full、restore_read_only、message_version_changed。未知存储故障不返回持久化成功；不回传 SQLite 错误或上游敏感错误正文。

线程列表附加 `message_revision`（持久化的消息变化标记）与 `message_activity_at`（已观察可见消息活动时间，毫秒），用于未读与排序；`revision` 仍是续聊校验使用的完成轮次 ID，`updated_at` 沿用秒单位。正文新增、版本/排序改变及删除推进消息标记；重放不推进。消息状态与正文、事件同一事务保存，副本删除和 collection 重置一并清理。旧 Hub 数据迁移保留既有已读基线，旧 Android 可忽略新增字段。

## 发送及恢复

同一设备/请求 ID 唯一，摘要包括完整目标与负载。同键异内容拒绝。Hub 提交事务后返回 accepted；分发前落盘 dispatching；Agent 保存 intent 后调用原任务，权威轮次 ID 到达才记 codex_accepted。任何副作用临界区断线转 unknown，不自动重发；迟到回执可消除未知。命令接收、分发、过期、取消、恢复与回执变化均事务性写入 command 同步事件。没有 Agent 在线时，手机查询回执也会把到期命令落盘为 expired。Agent 重连按 rowid 顺序每批 128 条重放全部持久回执，不重新执行副作用；因此恢复耗时仍随账本规模增长。

请求提交时间窗口 120 秒，命令有效期 60 秒。同一任务存在 accepted/dispatching/unknown 时拒绝第二个命令；busy/offline 保留手机草稿。上游没有原子条件提交，状态复查与 turn/start 之间仍有桌面同时操作的竞态，必须实测后决定可用范围。

明确源删除创建 tombstone、移除对应正文并发同步事件；旧 snapshot 不能恢复该内容。源暂时不可见不当作删除。当前正式适配器未取得经过验证的桌面删除事件来源，不能声称已验证自动追踪原桌面删除。

快照写入在读取事务内的 tombstone、revision 等状态前，以 `BEGIN IMMEDIATE` 取得写入权限。这样并发 Hub、采集与队列进程按 busy timeout 等待，而不会因 WAL 延迟事务从读取升级为写入时立即报锁冲突，造成间歇性的 `completion_projection_failed`。等待超时或其他真实导入失败仍保留告警；同步日志记录对应会话与错误原因。

## 默认限制

| 作用位置 | 默认值与超限行为 |
|---|---|
| 主机 / WS | 4 个 Agent、12 条 WS；重复主机连接拒绝 |
| HTTP | 32 并发、64 KiB 请求体 |
| 协议帧 / 上游响应 | 1 MiB，超限错误，不截取尾部冒充增量 |
| 单消息源正文 | 当前最多 256 KiB；更大明确报不支持，不静默截断 |
| 手机正文页 | 16000 Unicode 字符；可逐段读全文，纯文本降级 |
| 命令 | 正文 32000 UTF-8 字节；未解决命令全局 128 条 |
| 历史投影 | Hub 每页最多 30 条且前段 JSON 约 256 KiB；手机可视窗口及磁盘最多 5000 条消息；草稿和待确认独立保护 |
| 上游读取 | 20 任务/页、3 轮完整历史/请求；根据元数据变化读取，200 个元数据缓存上限 |
| SQLite | 单连接、2 MiB 页缓存建议值、262144 页数据库硬上限（默认页大小时约 1 GiB）；WAL、进程 RSS 另计 |
| 事件 / 通知 | 10000 条事件窗口；通知 24 小时有效，最多重试 5 次，指数退避；升级前缺少过期时间的旧 outbox 不回放 |
| 网络 | 上游响应 12 秒；写 socket 5 秒；WebSocket 慢读断开，不堆积无限队列 |

这些是实现默认值而非测量成绩；暂未提供每项参数热配置。SQLite 硬限额触发停止接收，尚未实现自动磁盘额度回收。手动维护前保护账本与未知命令。

## 验证

`cargo test` 覆盖去重、异内容冲突、崩溃恢复、迟到回执、身份隔离、撤销、一次性配对、长中文正文、删除 tombstone、一致性备份及分发前取消。`tests/integration/smoke.py` 使用真实 HTTP/WebSocket 与隔离演示 Agent，验证从配对到消息回执及恢复的纵向链路。四台实机压力、磁盘满故障注入、长时间资源曲线仍待验收。

## 分页与恢复边界

消息页按 `(ordinal DESC, id DESC)` 排序。调用方必须使用返回的 `next_before` 与 `next_before_id`，不能以少于 30 条判断历史结束。旧 `before` 参数保留兼容，但无法可靠遍历相同 ordinal 的边界。首段页限制避免长中文响应超过 Android 1 MiB 上限，完整正文仍通过版本绑定的 body 接口读取。

已撤销或过期的 Agent 不再被标为在线或可续聊。远程 Agent 的入站帧与消息均限 1 MiB，握手限 12 秒。历史补载不产生完成通知；每个首次观察到的任务均抑制旧完成通知。缓存淘汰后重新发现的任务同样保守抑制首次通知。

通知 outbox 的稳定键防止投影重复入队，不能消除网络超时后第三方已接收而本地尚未确认所产生的重复投递。任务列表跨页快照一致性、源修订顺序、真实四主机压力、公网推送与锁屏时延、长时间资源曲线仍需验收。

当近期快照的 revision 改变时，保守地将历史补载游标重置为该快照的 nextCursor，避免离线期间新增多轮超出近期窗口后，中间历史失去加载入口。相同 revision 的轮询保留已补载进度。此策略可能重新导入已有历史，按消息键幂等合并，不凭旧的“历史已到底”推断新旧窗口连续。

## 同步副本与 collection

`POST /v1/threads/{id}/delete` 需手机鉴权，仅删除 ThreadBridge 副本并持久 tombstone；旧 snapshot 和采集不能恢复该对话。原 Codex 记录保留。`GET /v1/capture-health` 返回有界捕获健康状态，需鉴权。

线程与事件响应包含 collection generation。手机先核对同一 generation，再事务性同步；代际改变时清理旧缓存、草稿、待确认状态与游标，保留配对。采集策略以完整现存 ID 排除集和创建起点阻止旧 thread 回流；必要去重意图和 unknown 保留。详见 [产品约束](../产品约束.md)与[Codex 接入](Codex接入.md)。

## 项目与手机新建

`GET /v1/hosts` 提供可选 `projects` 目录列表；原生索引同步已注册项目、根目录、project_id 和 cwd 元数据，不接入被排除旧对话的正文。目录独立保存在 `captured_project_catalog`、Hub `host_projects`、Room `projects`；每设备最多 100 个项目、128 KiB JSON（含旧 projects 与新增 project_details 名称信息）。

可选 `project` 字段传递归属项目根目录，`project_name` 传递注册名称，Hub 以独立 `thread_projects` 表保存；旧来源缺少元数据时为空。project_metadata 优先显式 project_id，其次最长已注册根路径（含同库工作树），其余为空；旧索引无项目表时兼容 cwd；不读取工具/推理内容作为项目。消息接口增加 `timestamp_ms`，旧客户端仍按 ordinal 分页。

`POST /v1/threads/create` 仅接受已配对手机、活跃且已验证启用 queue 的设备及该设备已知项目目录或已经同步的项目路径（空值为默认目录）。请求带 UUID、创建时间及第一条用户文字；Hub 先保存命令，设备先保存创建意图，然后使用同版本 desktop proxy 的 `thread/start`（继承现有权限），保存新原生 ID 后 queue 人类文字。未知创建或 queue 结果不自动重试，原不可变请求可查询。`GET /v1/commands/{id}` 返回可选 `result_thread_id`；手机按该字段切换到新对话。原始桌面记录与项目文件不因手机本机清理而修改。

`GET /v1/threads?q=…` 对标题作顺序片段匹配（中文、逐码点 Unicode 大小写归一、全角 ASCII 折叠、忽略查询空白），与手机使用相同规则流式匹配标题，百分号和下划线按字面检索，沿用鉴权、collection generation 与 50 条分页；查询最多 64 字符。普通查询仍返回原有分页列表。手机仅缓存实际打开的搜索结果，过期清理不删除 Hub 检索来源。新建、项目元数据及服务端搜索需要部署匹配版本的 Hub、bridge、远端 helper；已安装 APK 本身不升级电脑服务。

`project-align` 默认只读规划，`--apply` 刷新项目元数据且只更新 Hub 已有 host/native ID 的归属，缺失索引记录显示项目待同步，不导入历史正文。captured_projects/captured_project_catalog/captured_project_names 构成权威元数据快照；Hub project_names 保存名称。对齐及程序切换先备份数据库/配置，确认无 accepted/dispatching/intent，并核对正文、凭证、collection、tombstone、冻结 unknown 账本不变；`scripts/align_runtime.py --apply` 自动回退仅恢复程序定义和 fleet，逐个尝试恢复所有原 active 服务并报告残余失败，保留已对齐元数据。若需要回退错误的归属，在停下同步写入后，仅从私有备份恢复捕获库的 captured_projects/captured_project_catalog/captured_project_names 与 Hub thread_projects/host_projects/project_names 对应主机记录，再启动原服务；不能旧整库覆盖最新发送账本。

`project_known` 区分已核对且无归属（其他）与尚未升级/失联设备缺少元数据（项目待同步），后者不当成已知的空项目；不凭标题猜测离线主机归属。
